# Contributing to EarthData

## Development setup

```bash
python3.13 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
```

Tests spin up their own ephemeral PostgreSQL database per test via
`pytest-postgresql`; you need local `postgres`/`initdb`/`pg_ctl` binaries on
`PATH` (e.g. `brew install postgresql@16` on macOS, `apt-get install
postgresql` on Debian/Ubuntu). A running server is only required for
`docker compose up` / manual `uvicorn` runs, not for the test suite.

## Before opening a pull request

Run the full local check suite — CI runs the same steps and will reject
anything that fails here:

```bash
ruff check .
black --check .
mypy .
pytest
```

- `pytest` enforces 100% coverage (`--cov-fail-under=100`); add tests for
  any new code path.
- `black .` / `ruff check --fix .` to auto-fix formatting/lint issues before
  committing.

## Code style

- Type hints everywhere; `mypy --strict` must pass with no `# type: ignore`
  unless the comment explains *why* (third-party stub gap, documented
  library quirk).
- Docstrings only where the *why* isn't obvious from the signature — no
  restating the function name in prose.
- Follow the existing layering: `api` → `services` → `repositories` → `db`.
  Endpoints that are pure CRUD may call repositories directly; anything with
  actual business logic (validation, transformation, aggregation) belongs in
  a service.
- No new abstractions, feature flags, or config options for hypothetical
  future needs — match the scope of the change.

## Commit / PR conventions

- One logical change per PR; keep unrelated formatting/refactors out of
  functional PRs.
- PR description should state *why*, not just *what* — the diff already
  shows what changed.
- Update `CHANGELOG.md` under `[Unreleased]` for any user-facing change.

## Database migrations

Never hand-edit an already-merged migration. To change the schema:

```bash
alembic revision --autogenerate -m "description"
alembic upgrade head
```

Review the autogenerated migration before committing — Alembic's diffing is
not always exact (e.g. server-side defaults, index naming).

## Reporting issues

Include: EarthData version (`GET /api/v1/version`), Python version,
whether you're running via Docker or locally, and steps to reproduce.
